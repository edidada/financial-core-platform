# ADR-0002：金额以 BIGINT 最小货币单位存储

- 状态：Accepted
- 日期：2026-11-14
- 相关：`accounting-design.md`、`database-design.md`、`README.txt` 4.1

## 背景

货币计算不能用二进制浮点（`double`/`float`），否则 0.1 + 0.2 类误差会在复式记账的借贷平衡校验中造成假性不平衡。`README.txt` 4.1 明确建议使用 BIGINT 最小单位或明确精度的 DECIMAL。

需要在 `BIGINT(分)` 与 `DECIMAL(p,s)` 之间定一个统一约定。

## 决策

**阶段一统一用 `BIGINT` 存储最小货币单位（分，CNY 下 1 元 = 100 分）**，字段一律命名 `*_minor`（如 `amount_minor`、`available_balance`）。

- 应用层用 `long` 运算，禁止任何 `double`/`float` 参与金额计算。
- 展示层才做「分 → 元」格式化，且只在边界转换一次。
- 币种单独用 `currency CHAR(3)` 记录；不同币种不得进入同一凭证。
- 除法（如手续费、利息、净额分摊）必须定义明确的舍入规则与余数归属，且分摊后仍须满足 ΣD=ΣC（阶段二手续费模块再细化）。

## 备选方案

| 方案 | 优点 | 否决原因 |
| --- | --- | --- |
| `double` / `float` | 方便 | 二进制浮点误差，金融禁用 |
| `DECIMAL(20,4)` | 直观、支持小数 | 与 BIGINT 相比运算略慢；且易出现「同一系统两种精度」不一致。可作阶段三多币种/利率场景补充，阶段一不用 |
| 自定义 Money 类但底层 double | 面向对象 | 底层仍是浮点，无意义 |

## 后果

**正面**
- 加减法完全精确，借贷平衡（`ΣD=ΣC`）可用整数相等严格判定。
- 与 DB CHECK、索引聚合、离线重算天然一致。
- 避免跨语言/跨服务的精度歧义。

**负面 / 代价**
- 所有金额需带单位语义，API 文档必须写明单位，否则易被误当成「元」。
- 需显式处理币种最小单位差异（如 JPY 无分、部分币种 3 位小数）；阶段一仅支持 CNY 2 位小数，多币种扩展时引入 `currency.exponent` 元数据表。
- 展示与报表必须统一格式化工具，禁止各处自行 `/100`。

## 验证

`database-design.md` 中所有金额列为 BIGINT；`test-strategy.md` 属性测试中包含大量随机金额的借贷平衡断言，误差必须为 0。
