# 阶段一需求规格：金融账务核心

> 版本 v0.1 · 状态：设计中 · 对应 `README.txt` 第九节「阶段一（第 1–2 个月）」

## 一、目标与定位

阶段一交付一个 **模块化单体（Modular Monolith）** 的 Java 21 金融账务核心，用 **单库事务** 证明以下命题：

> 在并发、重试、超时与故障条件下，系统不出现重复扣款、超额扣款、不平衡分录或账务丢失。

阶段一 **不做**：服务拆分、Kafka、分库分表、多活、Flink/Spark、K8s。这些是阶段二~五的内容。

数据库默认使用 **本机 MySQL 8**，同时保留 PostgreSQL 支持：两种数据库共用同一套业务代码与事务语义，通过 Spring profile 切换（见 [ADR-0006](adr/0006-multi-database-support.md) 与 `database-design.md` 第十节）。

## 二、业务域与术语

| 术语 | 定义 |
| --- | --- |
| 交易 Transaction | 一次资金转移的业务意图，有完整生命周期与状态机 |
| 账户 Account | 资金归属主体；`available_balance` 可用余额、`frozen_balance` 冻结余额 |
| 分录 Entry | 复式记账的最小记账单位，分借方 Debit / 贷方 Credit |
| 凭证 Journal | 一笔业务对应的分录集合，必须借贷平衡 |
| 冲正 Reversal | 通过生成反向分录撤销已入账交易，不删除原分录 |
| 幂等键 Idempotency-Key | 客户端生成的唯一业务请求标识，相同键只生效一次 |
| 权威数据源 | 关系数据库中的余额与分录，是资金正确性的唯一判定依据 |

## 三、功能需求

| 编号 | 需求 | 验收要点 |
| --- | --- | --- |
| FR-1 | 开户与账户查询 | 账户唯一、币种/账套明确、余额初始为 0 |
| FR-2 | 充值 / 扣款 / 转账 | 转账为原子操作：转出与转入同时成功或同时失败 |
| FR-3 | 交易状态机 | 合法迁移见 `transaction-design.md`；禁止非法跳转 |
| FR-4 | 幂等 | 相同幂等键重复提交，返回首次结果，不重复入账 |
| FR-5 | 复式记账 | 每笔凭证满足 ΣDebit = ΣCredit（同币种、同账套） |
| FR-6 | 冲正 | 已入账交易可冲正；生成反向分录，原分录保留可追溯 |
| FR-7 | 并发资金安全 | 余额不足时并发扣款只允许成功足额的部分，不超扣、不丢失更新 |
| FR-8 | 交易结果查询 | 超时后可按交易号/幂等键查询最终状态 |
| FR-9 | 账务不变量校验工具 | 可离线校验「余额 = 分录累计」「借贷平衡」「无重复入账」 |
| FR-10 | 多数据库支持 | 同一套业务代码可运行于 MySQL 8（本机默认）与 PostgreSQL，profile 切换、Flyway 按厂商加载迁移 |

## 四、非功能需求（第一阶段 MVP 验收目标）

取自 `README.txt` 第一节，均为 **分阶段工程验收目标**，非企业内部生产指标推断。

| 指标 | 阶段一目标 | 备注 |
| --- | --- | --- |
| 交易 API 吞吐量 | 500 TPS | 固定硬件、真实业务混合、稳定负载 |
| 账务入账吞吐量 | 300 TPS | |
| 核心交易 P99 延迟 | < 200 ms | |
| 查询 API P99 延迟 | < 100 ms | |
| 核心服务月可用性 | 99.9% | 阶段一单实例 + 主备 DB |
| 同城故障恢复 RTO | < 30 min | |
| 灾难恢复 RPO | ≤ 5 min | |
| 已确认账务记录丢失 | **0** | 硬约束 |
| 重复请求导致重复扣款 | **0** | 硬约束 |
| 不平衡会计分录 | **0** | 硬约束 |
| 数据库兼容性 | MySQL 8（默认）/ PostgreSQL | CI 用 Testcontainers 双库跑同一套集成测试 |

必须区分：交易请求 TPS ≠ 数据库 SQL QPS；交易成功 ≠ 银行间最终结算；不丢账 ≠ 消息恰好投递一次。

## 五、资金正确性不变量（硬验收条件）

| 编号 | 不变量 | 校验方式 |
| --- | --- | --- |
| I-1 | 任一凭证 ΣDebit = ΣCredit | 按 journal 分组聚合 |
| I-2 | 单账户余额 = 期初余额 + 历史分录累计 | 离线重算比对 |
| I-3 | 同一业务交易最多入账一次 | 唯一约束 + 幂等记录 |
| I-4 | 余额不为负（不允许透支账户） | CHECK 约束 + 条件更新 |
| I-5 | 已生效分录不可被修改或删除 | 只追加 + 权限/触发器 |
| I-6 | 冲正后净额为 0，且双向分录均可追溯 | 反向分录关联原凭证 |

详细定义与校验 SQL 见 `consistency.md`。
